## How the game uses DirectSound

Counted over the 5 runs above (1157 buffers, 237 of them copies).

- **Device.** `DirectSoundCreate(NULL)`, `SetCooperativeLevel(hwnd, DSSCL_EXCLUSIVE)`, `CreateSoundBuffer` with `DSBCAPS_PRIMARYBUFFER` (no format, 0 bytes), then `SetFormat` on the primary buffer: 22050 Hz, 16 bit, 2 channels. Nothing else is called on the primary buffer (no `Play`). Wine notes that it treats DSSCL_EXCLUSIVE like DSSCL_PRIORITY and mixes at its own device format (48000 Hz float); neither is a failure.
- **Buffer flags.** `0x000100E8` (LOCSOFTWARE | CTRLFREQUENCY | CTRLPAN | CTRLVOLUME | GETCURRENTPOSITION2) on 1157 buffers. No `DSBCAPS_CTRL3D` and no `DSBCAPS_STATIC`: position in the world reaches DirectSound only as volume and pan.
- **Formats.** 22050 Hz 8-bit mono: 687, 11025 Hz 8-bit mono: 75, 22050 Hz 16-bit mono: 65, 11025 Hz 16-bit mono: 40, 44100 Hz 16-bit mono: 25, 22050 Hz 16-bit stereo: 13, 11025 Hz 8-bit stereo: 5, 22050 Hz 8-bit stereo: 5, 44100 Hz 16-bit stereo: 5.
- **No streaming.** Each file is read whole, then `CreateSoundBuffer` (size = the WAV data chunk; all 920 checked against the files), `GetFrequency`, one `Lock(0, whole size, 0)`, one `Unlock`. No buffer is locked again later. The music is one static buffer too, 5 MB or more.
- **The format pointer** points into the file image, so `cbSize` is read from the bytes after the 16-byte PCM header: 24932 (0x6164 = "da" of the `data` tag).
- **Starting a sound.** `GetStatus`; if the buffer is already playing, `DuplicateSoundBuffer` + `AddRef` and the copy is used; then `SetVolume` / `SetPan` / `SetFrequency` only for values that differ from what the engine last set on that buffer; `SetCurrentPosition(0)`; `Play(0, 0, DSBPLAY_LOOPING or 0)`. 402 of 402 `Play` calls come directly after `SetCurrentPosition(0)`.
- **Copies start with the original's volume, pan and frequency** (Wine copies them; the DirectX documentation says the same). The game relies on it: 188 of 237 copies were played without any `SetVolume` call of their own.
- **Rare calls.** `Stop`: 5 calls (IdleFee1.wav x4, LV2snd1.WAV x1), each on a buffer that `GetStatus` had just reported playing. `SetFrequency`: 4 calls (IdleFee1.wav: 44100 x3, IdleFee1.wav: 0 x1); 0 is DSBFREQUENCY_ORIGINAL, the rate the buffer was created with. A looping sound in the world that should not be heard is not stopped, it is set to -10000.
- **Calls never made:** `GetCurrentPosition` 0, `Restore` 0, `GetVolume` / `GetPan` 0, a second `Lock` 0.
- **Polling.** `GetStatus` is the only read-back and is called constantly: 5208656 calls, 42391 / 9374 / 13628 / 27169 / 31450 per second. In world 1 the music buffer was asked 14122 times, once per frame; the 13 looping copies of forest3.WAV between 42356 and 211819 times, that is 3 to 15 times per frame: for every copy the engine walks the chain of copies again.
- **Release.** 181 `Release` calls, 0 on originals. A copy is released (reference count to 0) when it is found stopped the next time the same sound is started: 181 of the 181 directly follow a `GetStatus` that returned 0. A finished sound therefore stays allocated until then.
- **Volume.** Values from -10000 to -473. They follow `trunc(1000 * log2(v))` with `v` = `Volume.ini` value x `MasterVolume` x player volume / 100 x distance factor: a halving of `v` is -1000 (10 dB), and `v` = 0 gives -10000. Table below.
- **Pan.** Values from -1000 to 1000 (allowed: -10000 … 10000), so the engine pans by at most 10 dB. `SetPan` is called in every frame in which the engine's own value changed: 120870 calls, 52874 after merging repeats of the same integer.
- **Failed calls:** none. Wine logged no warning for any buffer call.

## What these runs do and do not show

- **Wine, not Windows 98.** The calls and their arguments are the game's. What a call does is Wine 11.20's DirectSound: that a copy starts with the original's volume, what `GetStatus` returns and when a buffer that is not looping counts as stopped.
- **Open: copies that never get a `SetVolume`.** Under Wine a copy made while the original is at -10000 is silent until the game sets its volume, and most copies of the looping world sounds never get such a call (world 1: 11 of the 13 copies of forest3.WAV). Microsoft's page for `DuplicateSoundBuffer` has a remark about a known issue: a duplicate plays at full volume until its volume is set to a value different from the original's ([IDirectSound8::DuplicateSoundBuffer](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ee418041(v=vs.85))). It does not say which Windows versions or drivers. If the Windows of 2000 did that with these buffers, the same copies were loud there instead of silent. Not established here; it needs a start of the original on Windows 98 (86Box).
- **Return values.** Wine's trace prints arguments, not HRESULTs. It prints a warning on every failing path of the buffer methods, and there was none, so every call is recorded as "ok". `GetStatus`, `GetFrequency`, `Lock` and the reference counts are real values.
- **Time.** There is no sound device. Wine's stream goes through ALSA's file plugin into `pace.py`, which takes it at the played rate; the mixer rate in the first table shows the play cursors ran at real time (48000 frames a second wanted). With ALSA's plain null device they run about 3.6 times too fast and every sound that is not looping ends early. Trace lines are stamped in whole milliseconds.
- **Frame rate.** The game has no frame limiter and ran at 170 to 600 frames a second on software OpenGL, so the number of `SetPan` and `SetVolume` calls says nothing about a real PC. Values and their times do. The clock of the run starts at 120 s, as on a PC that was just switched on.
- **First frame.** Observed: in the first frame after loading most world sounds are `Play`ed at -10000 and get their value in the second frame, 0.02 to 0.07 s later, and one copy can be at its full value for that one frame only (world 1: #182, -1625 from 0.001 to 0.054 s). Inferred, not checked in the code: the first frame works from a listener position that is not the camera's yet.
- **Run to run.** Two starts of world 1 give the same calls with times a few milliseconds apart; values that depend on the frame clock differ slightly (the music ends its fade at -988 or -989; rcland1.wav -2170 and -2163).
- **Settings.** Levels depend on the player's volume settings, here 80 and 80, and on `Volume.ini`. Difficulty 1; other difficulty levels were not run. The volume formula in this file is fitted to the trace and the INI values (exact to the unit for every file that reached its full value); the distance part was not worked out.
- **Not captured:** the bytes written into the buffers (only their sizes, equal to the WAV data chunks), anything after 42 s, the menu, the results screen, the end of a world and the shutdown (the runs end by killing the process, so the release of the original buffers is not in the trace). Walking was tried in world 1 only, 10 s forward; the player walks into an obstacle after about 2 s and the footsteps continue.
