Version 1.0.4 combines the game's JavaScript into one optimized runtime, reduces repeated CPU and memory work, and separates editable source from the files needed to play. It also includes the completed Android release tooling and updated project documentation. Existing player profiles, saves, recovery history and settings remain compatible without conversion or manual intervention.

## Runtime & Performance

- **Combined the game into one JavaScript bundle:** Normal gameplay now loads `src/game.bundle.js` instead of requesting 139 game modules and two Three.js modules separately. The initial bundle reduced JavaScript size by about 63% before HTTP compression. This improves startup delivery; it is not a claim of a specific gameplay FPS increase.
- **Reduced idle menu processing:** Controller navigation no longer scans every menu control on every neutral frame. Actual input, focus changes, hidden or disabled controls and new dialogs still use the current menu state. Unchanged touch-control contexts also avoid unnecessary allocations and updates.
- **Stopped redrawing an unchanged scoreboard:** After the debriefing fade finishes, the canvas retains its pixels until values, layout, artwork, fonts or graphics context change. The original appearance, fade timing and continue behavior remain intact.
- **Reduced repeated positional-audio work:** Physical door portals are evaluated once per update instead of once per directed connection. Unchanged volume and stereo-gain values are no longer sent repeatedly to the audio backend, and pickup-sound completion checks avoid temporary arrays. Hearing ranges, obstruction, fades and the intentional sound/music scheduling remain unchanged.

## Source Layout & Development Tools

- **Separated editable modules from the runtime:** The individual JavaScript files now live in `source/`, with a README explaining their development role. `src/` holds the generated bundle, debugging source map and runtime CSS. Prepared desktop, browser and Android games do not require the editable `source/` directory; independent actor, coin and shove test rooms retain their own source layouts.
- **Made bundle preparation automatic:** Development startup, the local web server, desktop packaging and Android asset preparation regenerate the runtime from the validated source snapshot. The pinned bundler preserves public property names, class/function names, asset URLs and initialization behavior. Dependency changes update the cache revision, and debugging maps refer back to the readable source.
- **Made the local web server more memory-efficient:** Files stream with backpressure instead of being buffered in full for each request. Media seeking uses byte ranges, `HEAD` returns headers without a body, unchanged files can return `304`, and disconnected clients release their file streams. The existing loopback origin and saved browser progress remain unchanged.
- **Reduced Android preparation memory use:** Assets are copied and hashed in bounded chunks, and staging directories are created once. Output manifests still describe the exact copied bytes; validation, atomic replacement and rollback remain in place.
- **Updated active browser checks for the restored menu:** Ten affected harnesses now share navigation through the actual original-menu controls and settings submenus, including touch taps. Historical flat-menu checks are identified as historical rather than presented as current release gates.

## Android

- **Completed signed Android release preparation:** Added a reproducible helper for signed APK and Google Play AAB output, private upload-key configuration, runtime manifests and checksums. Signing credentials remain outside the repository and release files. The app targets Android 16/API 36 and supports installation from Android 10/API 29, subject to compatible WebView/WebGL support.
- **Fixed Android audio-focus suspension:** Removed a competing Activity audio-focus request that could pause the app when its own menu voices or movies began playing. WebView manages media focus, while Activity/window changes still suspend gameplay and audio. Hardware volume keys control game audio even when paused or temporarily silent.
- **Corrected automatic Android rendering limits:** The Android-only automatic resolution budget now respects both a 720-pixel short edge and a 1280×720 total-pixel budget while preserving the device's aspect ratio. Desktop and ordinary mobile-browser resolution behavior is unchanged.
- **Added reproducible Play publication and privacy guidance:** Documentation covers signing continuity, offline assets, local player data, document-picker save import/export, store declarations and remaining physical-device checks. Android's Over screen includes the privacy information. Compilation does not imply Google Play publication or approval.
- **Kept Android evidence scoped to its build:** The completed signed Android 1.0.3 APK/AAB and its Android 16 debug-emulator results predate the later bundling and source-layout changes. They are retained as historical evidence, not presented as tests of the 1.0.4 packages.

## Documentation, Research & Save Compatibility

- **Reconciled current guidance with the actual source layout:** README, build, Android, hosting, import and publishing instructions now distinguish editable modules from deployable runtime files. Current platform status has one primary reference, stale local paths and broken current links were corrected, and historical research is explicitly separated from unfinished implementation work.
- **Preserved and published the complete original-code research:** The full `RC_ORIGINAL_DECOMPILED` folder is retained separately from the port, with instructions to include it in future source releases and research archives. Decompiled output remains inspection material rather than a claim that the original authored source was recovered.
- **Preserved existing saves and intentional changes:** Storage origins, keys, player IDs, save schemas, exported backups and recovery namespaces are unchanged. The modern controls, save features, camera protections, audio choices and gameplay corrections remain included. Earlier focused source checks restored old saves and recovery history without clearing or converting them.

## Release Scope

- **Updated the release version to 1.0.4:** Menu and package metadata identify this release. These notes cover changes after the **1.0.3 release commit, `1c788dd97`**; the original menu, combat corrections and other features already shipped in 1.0.3 are not counted again as new work.
- **Included desktop and Android packages:** Linux, Windows and macOS downloads cover x64 and ARM64. Android includes a signed direct-install APK and a Google Play AAB, with version name 1.0.4 and version code 6. Windows packages remain unsigned; the macOS bundles built on Linux remain unsigned and not notarized. No Google Play upload or approval is implied.
- **No new tests or build checks are run for this release pass:** Packages are compiled, archived and published under the requested build-only policy.
