# Actor ambient from the floor

Reference executable: original `RcHcGame.dat`, SHA-256
`e30781fcdc665d1f217c1a3353761c96e1ec3566f1ad472bb1a8a499cb29dba5`.

`gePuppet_ComputeAmbientLight` at `0x5ce190–0x5ce3a3` samples the baked floor beneath the actor's root position. This is a point query down 30,000 original units, not an actor hull query, a scene hemisphere light, or a sample at the head. The crossed BSP node determines an ordered range of faces; each candidate uses a bounding-box tolerance of 20 units. `Light_GetLightmapRGB` at `0x5d3b40` projects onto the original texture vectors, adds the authored shifts, subtracts the lightmap minima, divides by 16 and truncates to one integer luxel. It does not bilinearly interpolate. Each returned RGB channel is divided by 255 and capped at 0.3.

The implementation reads `lightmaps.bin`, already preserved from the original BSP. All five supplied maps contain only baked light style zero; the importer verifies that fact rather than silently discarding additional styles. Dynamic light contributions use the recovered fixed-point BSP luxel calculation before the ambient cap. Fullbright surfaces do not receive that dynamic contribution.

Shadow-casting dynamic lights follow the branch at `0x5d2225` into `CombineDLightWithRGBMapWithShadow` (`0x5d31f0`). An in-range sampled luxel is traced from the light against world BSP node zero with contents mask `0x43`; actors and moving brush models do not cast shadows in this routine. The endpoint uses the original `CalcSurfVectors` (`0x5d4f50`) texture-to-world vectors and sits one unit above the oriented face plane. Its unusual use of the texture vectors' Z components, rather than texture shifts, is present in both the binary and the reference source and is retained. Visibility is cached by face, integer luxel and exact light position in a bounded 4,096-entry map; color/radius pulsation does not rerun an unchanged shadow ray. The tower's authored `CastShadow=1` light flags now reach this sampling path.

The new `actor-floor-lighting.json` files preserve original node face ranges, face bounds, raw texture frames and lightmap offsets. They are generated by `tools/import_actor_floor_lighting.py`, which checks the original BSP SHA-256 and the existing collision-node order. The regular level importer also writes the metadata. Updating these files does not regenerate meshes, textures or packages.

Performance is bounded by the BSP query and a local face lookup. Large coplanar nodes use a grid built once when the level loads, preserving original face ordering. An actor-owned weak cache reuses its floor lookup while its root remains stationary; current dynamic lights are still evaluated each frame. The original trace tests models in authored order, so a world floor wins even when a moving brush is closer. When the world trace misses, the sampler also tests brush models in their transformed space. `beginFrame()` compares model transforms once per frame and invalidates fallback caches only when those transforms or enabled states actually change. No per-frame mesh traversal, triangle raycast, image readback or atlas decoding is used.

Portable safeguards and remaining limits:

- A start inside solid space or missing floor normally returns the configured actor ambient; decorative corner trees opt into the bounded recovery described below. When every native face sample fails, a second pass can recover the same floor's physical lightmap coordinates without texture-art shifts. It requires the point to lie inside the face bounds (0.001-unit numerical tolerance), retains native face priority and the 0.3 cap, and leaves valid black samples untouched. If recovery also fails, configured ambient applies. The original unsuccessful-face branch could accidentally retain the preceding actor's global ambient; that cross-actor leak is not reproduced.
- A coordinate exactly one sample beyond a map is clamped to its edge rather than reading adjacent memory, while all valid authored luxels retain native indexing.
- The shadow branch described above fixes actor ambient sampling. The renderer's separate world-surface dynamic-light shader has its own presentation limitations; this change does not add shadow rendering to world geometry.
- The explicit contents mask avoids the native floor routine's dependence on a mutable global mask left by previous unrelated traces.

Focused checks: `node --test tests/actor-floor-lighting.test.mjs` covers exact point intersections, nearest-luxel indexing, authored shifts, bounds tolerance, ambient cap, dynamic contribution, stationary caching, authored model priority, transformed brush fallback, native shadow endpoints, wall occlusion, stable shadow caching and bounded sampling in all five imported levels. `python3 tools/import_actor_floor_lighting.py --check` verifies metadata against all five original BSP files.

## Hand-torch regression correction

Six `htorch.act` instances in Het Kerkhof (`AdamAnyActor37`, `90`, `132`, `133`, `139`, `141`) stood above floors whose texture shifts invalidated every native luxel lookup. For the entrance pair (`132` and `133`), the separate Sun reference also lies inside the roof. Replacing the native failed-face ambient leak with zero therefore rendered the hands and sticks completely black, although their separate flame effects remained lit.

The recovery pass samples the actual baked floor lighting instead of borrowing an unrelated actor's ambient or making the torch emissive. All 24 graveyard hand torches now have valid ambient; the eight castle hand torches retain their original successful samples. Geometry, animation, Sun visibility and flame effects are unchanged. Recovery is cached with the ordinary floor result, so animating a stationary hand adds no repeated floor queries.

Focused regression checks: `node --test tests/hand-torch-lighting.test.mjs` and `node tests/hand-torch-lighting-scenes.mjs`. The latter renders the entrance pair, checks actual pixel illumination, checks all 24 graveyard uniforms, and exercises the animation/cache path. This is a deterministic repair of invalid native sampling, not a claim to reproduce the old draw-order-dependent ambient leak exactly. No package build is needed.

## Forest corner-tree recovery

All 60 `tree.act` corner decorations in Het Bos have origins buried inside the authored segment walls. Their floor trace starts in solid space rather than crossing a floor, so the shifted-coordinate recovery used by the hand torches cannot help. The separate local Sun lookup can also fail, leaving black trunks and foliage. The three standalone `tree2.act` instances already have valid floor lighting.

Only `tree.act` opts into an additional recovery pass. When its root starts in solid space, the sampler tries at most five points inside the tree's transformed setup bounds: the center and four horizontal sides at one quarter of its height. The first valid floor supplies its original lightmap color, including a legitimately black sample; the normal 0.3 ambient cap and dynamic-light calculation still apply. It does not change tree geometry, collision, Sun visibility, or other actors' handling of buried origins. This is a local compatibility repair, not an assertion that native Genesis3D used these probes.

The recovered surface and a numeric snapshot of the bounds are cached per actor. Position or bounds changes invalidate the result; recovered brush floors also track brush changes. A stationary tree incurs no further BSP searches. The imported forest needs 130 additional point queries once to recover all 60 corner trees; it does not scan scene triangles or add a per-frame lighting search.

Focused checks: `node --test tests/forest-tree-lighting.test.mjs` covers explicit opt-in, local probe limits, dark samples, missing floors, cache invalidation, all 60 corner trees and the three unchanged standalone trees. `node tests/forest-tree-lighting-scenes.mjs` checks all live tree uniforms, rendered corner-tree pixels, unchanged placement and zero repeated BSP work across 60 updates. No new package build was generated.
